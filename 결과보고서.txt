[defense.jbnu.ac.kr 취약점 조치 결과]

1.
- 점검 항목: SRI(Subresource Integrity) 지원 검사
- 취약점 조치: 조치 완료
- 처리 방법: 외부 Pretendard CSS에 SHA-384 무결성 해시와 crossorigin="anonymous" 속성을 적용함.
- 적용 페이지: index.html, sitemap.html 및 pages 폴더 내 전체 HTML 페이지(총 25개)

2.
- 점검 항목: 안전하지 않은 써드파티 링크(target="_blank")
- 취약점 조치: 조치 완료
- 처리 방법: 새 창으로 열리는 외부 링크에 rel="noopener noreferrer"를 적용하여 window.opener 접근과 Referer 전달을 차단함.
- 적용 페이지: pages/people/faculty.html 및 target="_blank"를 사용하는 전체 페이지

3.
- 점검 항목: 누락되었거나 안전하지 않은 X-Content-Type-Options 헤더
- 취약점 조치: 호스팅 서버 설정 필요
- 처리 방법: GitHub Pages에서는 저장소 코드로 HTTP 응답 헤더를 설정할 수 없으므로, 프록시/CDN 또는 별도 웹 서버에서 X-Content-Type-Options: nosniff를 설정해야 함.
- 적용 페이지: 사이트 전체

4.
- 점검 항목: 누락된 Content-Security-Policy 헤더
- 취약점 조치: 부분 조치(서버 설정 필요)
- 처리 방법: 전체 HTML에 upgrade-insecure-requests 정책을 적용함. HTTP 응답 헤더 방식의 상세 CSP는 프록시/CDN 또는 별도 웹 서버에서 설정해야 함.
- 적용 페이지: index.html, sitemap.html 및 pages 폴더 내 전체 HTML 페이지

5.
- 점검 항목: 불필요한 HTTP 응답 헤더(Server) 노출
- 취약점 조치: 호스팅 서버 설정 필요
- 처리 방법: 노출된 Server: GitHub.com 헤더는 GitHub Pages가 생성하므로 저장소 코드에서 제거할 수 없음. 프록시/CDN 또는 별도 웹 서버에서 응답 헤더 제거가 필요함.
- 적용 페이지: 사이트 전체

6.
- 점검 항목: 지나치게 허용적인 CORS 액세스 정책
- 취약점 조치: 호스팅 서버 설정 필요
- 처리 방법: Access-Control-Allow-Origin: * 헤더는 GitHub Pages가 생성하므로 저장소 코드에서 변경할 수 없음. 프록시/CDN에서 허용 출처를 제한하거나 해당 헤더를 제거해야 함.
- 적용 페이지: 사이트 전체 정적 자원

7.
- 점검 항목: 누락된 Referrer-Policy 보안 헤더
- 취약점 조치: 조치 완료(HTML 정책 적용)
- 처리 방법: 전체 HTML에 <meta name="referrer" content="strict-origin-when-cross-origin">를 적용하여 교차 출처 요청 시 원본 정보만 전달하도록 제한함.
- 적용 페이지: index.html, sitemap.html 및 pages 폴더 내 전체 HTML 페이지(총 25개)

8.
- 점검 항목: 이메일 주소 패턴 발견
- 취약점 조치: 공개 필요성 검토
- 처리 방법: 교수·직원 및 교육과정 담당자의 공식 문의용 주소로 확인되어 서비스 기능 유지를 위해 보존함. 비공개 주소가 포함되지 않도록 운영 시 정기 검토가 필요함.
- 적용 페이지: pages/people/faculty.html, pages/people/staff.html, pages/program/defense-manager.html

[서버 설정 권고값]
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Access-Control-Allow-Origin: https://defense.jbnu.ac.kr (교차 출처 제공이 불필요하면 헤더 제거)
Server: 제거 또는 최소화
